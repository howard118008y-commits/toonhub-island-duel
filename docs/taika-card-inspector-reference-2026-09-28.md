## 台卡建議佈局與互動（我方設計建議，非暴雪實作宣稱）

1. 桌機保留「上商店、中5格棋盤、下3手牌」；右側約300px木框角色介紹預留位置，切換卡牌時不讓棋盤寬度改變。資訊順序：地域／職業 → 肖像 → 攻擊與目前生命 → 階級／普通或金卡 → 完整技能 → 羈絆 → 台詞與角色小傳。
2. 滑鼠停留或鍵盤聚焦只做唯讀預覽；點擊固定介紹，同時維持現有自有牌 select／點放功能。拖曳超過既有閾值後不得誤開或切換面板；購買、出售、開戰仍只由原操作執行。可考慮100ms預覽延遲避免掃過閃爍，此數字是本作建議。
3. 面板只更新自身內容，不重建整個棋盤、不移動焦點、不重新建立動畫。已固定角色以UID追蹤，目前數值取正在顯示的戰鬥快照；普通商店卡可用cardId。售出／死亡不能把舊角色介紹轉綁到補位角色；可清空或明確顯示已離場。
4. 窄螢幕採可關閉的側抽屜，點卡／詳情開啟；不把300px硬塞在5格旁。保留清楚關閉、Escape、原焦點回復；懸停不能是唯一入口。正在拖曳時介紹不得遮住商人或落點。
5. 「能力」來自真實遊戲資料；「角色小傳」為台卡原創地域角色故事，與技能和台詞分開。台卡目前description主要是規則，不能把它冒稱背景故事；故事不得暗示所有真實住戶都有某個性格。

## 本輪交付驗收條件

- 商店、己方場上／手牌、敵方與戰鬥中角色都能查看；普通／金卡、基礎／當前攻血明確區分。
- 預覽與固定資訊本身不觸發交易、開戰或換位；既有「選牌→點位」的明確排位操作保留，拖曳買入、部署、換位、出售與1倍碰撞維持可用。
- 故事和技能都可閱讀，長文可捲動且不遮主操作；面板關閉不丟本局、不重播木盒。
- 死亡、召喚補位、出售與新局後無錯UID、過期數值、殘留timer或事件；桌機與375窄短畫面分別驗收。
- 台卡繼續使用原創美術、24張卡、單機5／3格；本輪研究不構成8人模式、卡池、抽包、戰鬥數值或暴雪素材複製需求。
