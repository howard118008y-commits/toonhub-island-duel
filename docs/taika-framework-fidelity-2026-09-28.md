## 優先順序與整合邊界

1. **先修框架**：可操作入口物件 → 中央木盒模式選單 → 商人／玩家兩端及手牌層級。先能一眼看懂功能，再加材質。
2. **保留已通過的規則**：同一購買 API、pointer 路徑、5／3 容量、1 倍戰鬥、v2 舊存檔遷移與 PvE 帳本；此次不重新平衡。
3. **外層沉浸**：React 只保留 44px 深木細框、台卡與「返回網站」，不再顯示第二組遊戲流程。iframe 持續掛載、不加遮擋 HUD 的浮動按鈕或額外頁尾；遊戲內「大廳」由原 controller 管理。
4. **尺寸與可及性**：桌機和窄短手機視窗均看得到商店、落點、手牌和主操作；卡牌選中時也不能把手牌藏到操作列下面。保留焦點與按鍵等價操作，實體觸控未驗前不宣稱通過。
